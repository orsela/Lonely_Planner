## Step 3 — the page side `app/js/f14.js` (2026-11-15, branch `f14`, version 3.0.0-alpha.15)
<!-- CHANGE 2026-11-15 F14-DOCS-05: new section (no previous version). What changed from alpha.14 is in the header of app/js/f14.js. -->
- **Files:** `app/js/f14.js` (new), hooks in `app/index.html` (script tag F14-SCRIPT-01; gate hooks F14-GATE-01 / F14-GATE-02; main-script hook F14-MOUNT-01; `PT_VERSION` / `APP_VERSION` → `3.0.0-alpha.15`), `app/sw.js` (`js/f14.js` in `SHELL_FILES`, LEAN rule 7), `tests/f14/f14_test.mjs`, `tests/f14/test_f14_browser.py`, `tests/f14/run.sh` 1.2.0 (`--only app`).
- **Flag:** `CHAT_FEATURE` stays **`'soon'`** → nothing is attached, nothing is wrapped, the chat button is the old toast (browser test checks: no request, no F14 styles, sheet does not open). `'on'` is step 4.
- **How the request is rewritten (decision vs spec wording "wrap sendChatMessage"):** `sendChatMessage` builds its own request with the anon key and turns every non-200 into a random generic line, and `CHAT_ENDPOINT` is a `const`. Re-implementing it would copy ~60 lines of context building (F10 fx, journal, documents) and risk the CHAT-FIX regressions. So the wrapper `send()` only marks "a question is in flight", and a fetch hook (installed at mount, active only while `send()` runs, only for a POST to the exact chat endpoint) rewrites the request: `Authorization: Bearer <user JWT>` from `sb.auth.getSession()` (the anon key and the `apikey` header are gone), `trip_id`, `lang:'he'`, `tripInfo`, ISO dates / country / tz per day. No session → the "reconnect" line **without any request**.
- **Refusals** come back from the hook as a normal 200 `{answer: <friendly line>, action:null}`, so the page shows them as an ordinary assistant message, in the page's own flow, one request, no retry: 401 `unauthorized` (reconnect), 403 `not_member`, 429 `daily_cap` / `rate_limited`, 503 `chat_off` (line "הצ'אט יחזור בקרוב" + the old toast), 502 `upstream_error`, 504 and the page's own 40 s abort → `upstream_timeout`, 413 `too_large`. The code is the server's `error` field, else the HTTP status. 400 / 500 / no network are left alone (the page's old generic line). These lines are removed from `history` before the next request, so the model never sees them.
- **One question at a time** (small addition): a second Enter while an answer is pending is ignored, because every Claude call counts against the trip's 100 per day.
- **`tripInfo`:** `name`, `countries` (English names from `countries.json`, from the days' own `country`; a trip with none = F08's default), `homeCurrency` / `localCurrency` (`__ptF10`), `members` (count of active `trip_members`, cached 60 s; omitted if unknown), `today` (device date), `start` / `end` (ISO, from the days). **`homeCity` / `homeAirport`: no such field exists in the app today** — the keys are sent only if a `home()` getter is passed to `attach` / `mount`; nothing is wired, so the server's rule applies (TLV for an ILS trip, else it asks). To do when the app gets a home city.
- **`trip[]`:** `date` becomes ISO (the server's range logic needs it), `country` / `tz` for ordinary days. A **flight day gets `flight:{from,to}` (country, city) and no invented `country`** — F08's fallback for a day without one is the previous day, else `VN`, which would be wrong for the first flight of a Georgia trip.
- **FB_Chat card:** a `search_links` action → the assistant bubble + a card with the data of F24's `f24ChatSearch` (from / to or city, date(s), travelers, two links in a new tab with `noopener`). `missing[]` → one plain question line (the model's text is not shown; a date without a year counts as missing, F24 rule); `null` (F24 off, bad kind) → the bubble only; any other action type is dropped in the hook (D2). No approve / cancel button, nothing saved (the card is drawn from the stored `params` on every render, never stored itself). Offline → `<span aria-disabled>` instead of links + the offline line, repainted on `online` / `offline` while the chat is open (F24 C9).
- **Visual:** I did not re-open the `FB_Chat` artboard (LEAN rule 5); the card has its own `p14-*` styles in the F24 look (dashed green border, 48 px link buttons), not coupled to F24's CSS. **For Or's phone check: compare with the mockup.**
- **`STORAGE_BACKEND='local-only'` with `CHAT_FEATURE='on'`:** the button stays the old toast (F14-GATE-02), no request.
- **Tests:** `tests/f14/run.sh --only app` → Node 15/15 (request contents, JWT not anon key, no-session no-request, each refusal = one request, 400 / 500 / network untouched, D2, card, missing, null, offline, soon / local-only, one-at-a-time, chat_off toast) + ONE browser pass at 390 px with a stubbed endpoint (sheet opens, request headers and body, flight card links, hotel without a date, offline, five refusals with one request each, history without friendly lines, 44 px, no horizontal scroll, `'soon'` = no request).
