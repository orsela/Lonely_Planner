## 2. What was fixed in the harnesses (items 1, 3 and 5)

- **One place for versions.** `tests/qa_versions.json` holds the app version (3.0.0-alpha.7.1) and each function's
  FN_VERSION. `tests/qa_refs.py` reads it for the Python suites, and `tests/f05/function_test.ts` reads it for the
  function tests. Every older suite's APP_VERSION / PT_VERSION pin (F02, F03, F04, F05, F20, F04-HOME) now reads it, so
  those pins run instead of being deselected. Only the `<title>` version pins of F02 and F03 are deselected: since F04 §8
  the `<title>` is exactly "Lonely Planner".
- **Offline v2.15.2 baseline.** The repo history has no v2.15.2 app. e711542 is the first commit with `app/` (F02, built
  from v2.15.2). I compared its 7 protected declarations with v2.15.2 (orsela/Vietnam_Travel_Planner 630a8d8) and they are
  byte-identical, and so is every later commit of `app/index.html`. All suites now compare drawMap, drawGoogleMap,
  drawSchematicMap, fallbackToSchematic, SEED_DATA, stayBlock and bookingUrl with `git show e711542:app/index.html`
  (`qa_refs.V2152_REF`). The F02 parity dataset takes its SEED_DATA from there too.
- **F02 cases that run the whole old app.** ac05, ac09, ac10 and manifest_visible_fields still need a v2.15.2 checkout in
  BASELINE_DIR. Without one they now skip with that reason instead of failing.
- **No more network clone.** The clone was removed from `tests/f03`, `tests/f04`, `tests/f05` and `tests/f20` `run.sh`.
- **Old "before" references come from `qa_refs.REFS`.** F05 MAIN_REF = 4bd04e4 (alpha.5.1) and F20 MAIN_REF = a7c7a32
  (alpha.4.2). Both defaults used to be "main".
- **F05 standalone fake (item 3).** `tests/f05/harness.py` 1.0.1 now returns a plain-object MediaQueryList. The old fake
  threw on every `matchMedia('(display-mode: standalone)')` call. The app caught that error and fell back to
  `navigator.standalone`, which hid the bug. The new guard `test_h00_standalone_fake` checks it. Standalone cases re-run,
  all pass: b14[iphone_standalone], c03, c04 ×6, h00. The F06 suite has no standalone device, but it inherits the
  fixed `Env` and passes 70/70.
- **`run_all.sh` points the suites at the repo's `scripts/`.** The F02 import-tool case used to skip because of a stale
  default path.

## 4. App bugs (not fixed, reported)

A test is xfailed with the bug's id only when its failure is exactly that bug. Any other problem in the same test still
fails it, and the test passes again once the bug is fixed.

**QA-DEBT-BUG-01 · high (if the real Realtime behaves like the documented limitation).** `app/index.html` `subscribeMe`
(about line 3530, F06 C2) treats every Realtime `DELETE` event on `trip_members` as "my row was deleted" and never checks
`ev.old.id === mid`. Supabase does not filter DELETE events ("DELETE events only carry the row's primary key, so column
filters can't be evaluated"). So whenever a pending request is rejected or cancelled (a row DELETE), every member who has
the trip open gets screen 1.8b "כבר אינך חבר/ה…", and `cleanTrip` purges the trip's device data (queue, members cache,
vault DB).
Repro (QA fake, `tests/f05`): a trip with a manager M, an editor E and a pending "נועה". Both M and E have the app open.
M taps "דחייה" → "כן, לדחות". **Both** phones show 1.8b, and E's localStorage keeps only `pt:_device:removed`.
To confirm on the real project: two phones, reject a test request.

**QA-DEBT-BUG-02 · low.** When approve-member answers `not_manager`, the pending card stays visible: the app shows a toast
and repaints. F05 §1.5 says "not_manager → hide card".
Repro: demote the manager on the server without a Realtime event, then tap "אישור" → toast "רק מנהלים יכולים לאשר", and
the card is still there after 4 s.

**QA-DEBT-BUG-03 · low.** The role buttons on the pending card (צופה / עורך / מנהל) are 40 px tall. F05 §1 and criterion 15
require at least 44 px. Repro: a manager's home with one pending request at 390 px. The buttons measure 100×40 (v2) and
107×40 (v1).

**QA-DEBT-BUG-04 · low.** `/join/` `fatal()` writes a second `<main>` with `id="joinTitle"` into `#lpRoot`, while the hidden
F04 section `#m` with `#joinTitle` stays in the DOM, so the id appears twice. Repro: open `/join/#code=X` with
supabase-js blocked → the "לא הצלחנו לטעון את הדף" screen → `document.querySelectorAll('#joinTitle').length === 2`.

Still open from before: **F05-QA-D1** (approve-member has no version header).

## 5. How to run

```bash
tests/run_all.sh                  # every job, -j 2, about 18 min, one summary table; rc 0 = no failure outside the lists above
tests/run_all.sh --list           # job names
tests/run_all.sh -j 1 --only "f05 sup_f05_home fn"
QA_EXPECTED_VERSION=… / tests/qa_versions.json   # bump the versions here (once) on every release
```

- Logs go to `tests/.last_run_all_logs/<job>.txt`; the folder ignores itself in git.
- Needs pytest (the uv fallback path is added automatically), Playwright Chromium and Node 22.
- The DB job uses `service postgresql start` + `sudo -u postgres` and is skipped with a note if that fails.
- An optional BASELINE_DIR (a v2.15.2 checkout) adds the 4 F02 cases that run the old app. Without it they skip.
- Every deselection, with its reason and the feature that changed the behaviour, is listed in the header of
  `tests/run_all.sh`. Each superseded case also runs on a flag-off copy (`sup_*` jobs).
